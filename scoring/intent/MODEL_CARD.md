# Model Card — IntentNetworkModel v1.0.0

## Model Summary

| Field | Value |
|---|---|
| **Model name** | IntentNetworkModel |
| **Version** | 1.0.0 |
| **Type** | Binary logistic regression (sklearn Pipeline) |
| **Task** | Account-level intent classification — predict whether a B2B buying committee is in active buying motion |
| **Output** | `IntentScore` — probability converted to 0–100 scale + confidence ∈ [0, 1] |
| **Artifact** | `scoring/intent/artifacts/intent_model.joblib` |
| **Training script** | `scoring/intent/train.py` |
| **Minimum AUC-ROC** | 0.70 (Definition of Done gate; training script exits non-zero if not met) |

---

## Intended Use

harmoni uses `IntentNetworkModel` to aggregate weak intent signals from individual buying committee members into a single account-level intent score. The score drives NBA (Next Best Action) routing: accounts crossing the 70-point threshold are candidates for direct sales engagement or pricing conversation triggers.

**Out-of-scope use**: Individual contact ranking, lead scoring, or any surface that breaks the account-first rollup. Scores must never be attributed to individual contacts in user-facing output.

---

## Input Features

All features are computed by `scoring.intent.features.FeatureEngineer` from raw signal rows. The canonical ordering is defined in `scoring.models.FEATURE_NAMES`.

| # | Feature | Window | Description |
|---|---|---|---|
| 0 | `total_signals_7d` | 7d | Total signal events in last 7 days |
| 1 | `total_signals_14d` | 14d | Total signal events in last 14 days |
| 2 | `total_signals_30d` | 30d | Total signal events in last 30 days |
| 3 | `strong_signals_7d` | 7d | STRONG-strength signals in last 7 days |
| 4 | `strong_signals_14d` | 14d | STRONG-strength signals in last 14 days |
| 5 | `high_intent_signals_7d` | 7d | Pricing page / demo request signals (strongest predictor) |
| 6 | `high_intent_signals_14d` | 14d | High-intent signals in last 14 days |
| 7 | `negative_signals_7d` | 7d | Unsubscribes, bounces, spam reports (strongest negative) |
| 8 | `negative_signals_30d` | 30d | Negative signals over rolling 30 days |
| 9 | `unique_members_7d` | 7d | Distinct committee members active in last 7 days |
| 10 | `unique_members_30d` | 30d | Distinct committee members active in last 30 days |
| 11 | `channel_count_7d` | 7d | Number of distinct source channels active (WEB/EMAIL/CRM/WEBINAR) |
| 12 | `role_weighted_score_7d` | 7d | Σ(signal_strength × role_weight) for 7d member signals |
| 13 | `c_suite_vp_signals_7d` | 7d | Signal count from C-Suite and VP members in last 7 days |
| 14 | `committee_coverage_pct_30d` | 30d | Fraction of committee members with ≥1 signal in 30 days, capped at 1.0 |
| 15 | `velocity_7d` | 7d vs prior-7d | (signals_7d / signals_prior7d) − 1, clamped to [−1, 5] |
| 16 | `velocity_14d` | 14d vs prior-14d | (signals_14d / signals_prior14d) − 1, clamped to [−1, 5] |
| 17 | `days_since_last_signal` | All time | Days since last signal from any member; 999 if no signals ever |
| 18 | `decayed_score_7d` | 7d | Σ(strength_score × exp(−λ × days_old)), λ = ln(2)/7 (7-day half-life) |

**Preprocessing**: StandardScaler (zero mean, unit variance) is included in the joblib artifact pipeline. Inference requires no external scaling.

## Training Data

| Property | Value |
|---|---|
| **Source** | Synthetic — generated by `generate_synthetic_data()` in `scoring/intent/train.py` |
| **Samples** | 2,000 (default; overridable via `INTENT_N_SAMPLES`) |
| **Train / test split** | 80 / 20, stratified |
| **Label heuristic** | Weighted linear combination of features → sigmoid → threshold at 0.5 |
| **Label distribution** | ~50/50 by construction (sigmoid threshold at mean) |
| **Random seed** | 42 (overridable via `INTENT_RANDOM_SEED`) |

**Synthetic label weights** (strongest signals):

| Feature | Weight | Direction |
|---|---|---|
| `negative_signals_7d` | −0.30 | Negative |
| `high_intent_signals_7d` | +0.20 | Positive |
| `c_suite_vp_signals_7d` | +0.15 | Positive |
| `velocity_7d` | +0.12 | Positive |
| `strong_signals_7d` | +0.12 | Positive |
| `days_since_last_signal` | −0.05 | Negative |

## Evaluation

Evaluation is performed by `scoring.evaluation.harness.EvaluationHarness` on the 20% held-out test split.

| Metric | Value (seed=42, n=2000) |
|---|---|
| AUC-ROC | ≥ 0.70 (gate) |
| Threshold for `is_high_intent` | score ≥ 70 (probability ≥ 0.70) |

The training script calls `sys.exit(1)` if AUC-ROC < 0.70. CI/CD must run the training script and check for a zero exit code before promoting artifacts.

## Model Architecture

```
Pipeline([
    ("scaler", StandardScaler()),
    ("clf",    LogisticRegression(
                   C=1.0,
                   class_weight="balanced",
                   max_iter=1000,
                   random_state=42,
               )),
])
```

`class_weight="balanced"` corrects for class imbalance in real-world signal data where active accounts dominate.

---

## Known Limitations

1. **Synthetic training data**: The model is trained on synthetic data derived from hand-crafted heuristics, not real closed-won deal outcomes. Accuracy on real data will require periodic retraining against labeled CRM ground truth.

2. **Linear model**: Logistic regression cannot capture non-linear interactions (e.g., velocity is only predictive when combined with certain member seniority patterns). A gradient-boosted tree would likely outperform on real data.

3. **No temporal modeling**: Features are computed as snapshots. Time-series patterns (e.g., a sudden spike after a long silence) are only partially captured through velocity features.

4. **Committee size not a direct feature**: `committee_coverage_pct_30d` normalizes by committee size, but a very small committee and a large committee with the same coverage percentage represent very different sales situations.

5. **Cold start**: Accounts with fewer than 7 days of history produce unreliable scores; confidence will be low but the score is still emitted.

## Governance

- **Owner**: harmoni ML team
- **Review cadence**: Quarterly retraining review; trigger retrain when real-world AUC-ROC drops below 0.70 on backtested closed deals
- **Bias risk**: Accounts in industries with naturally low email engagement (e.g., government, legal) may be systematically under-scored. Industry-specific calibration is a future work item
- **Data privacy**: No PII is used as a model feature. All inputs are aggregated behavioral counts at the account level
